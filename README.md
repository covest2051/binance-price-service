# binance-price-service

Сервис по расписанию запрашивает у Binance среднюю цену торговых пар (`GET /api/v3/avgPrice`),
сохраняет её в PostgreSQL и отдаёт через REST: последнюю цену, среднюю за период, список с пагинацией и тренд.

Java 21, Spring Boot 3.5, PostgreSQL 16, Flyway, ShedLock, springdoc-openapi.
Тесты: JUnit 5, Mockito, Testcontainers, WireMock.

## Запуск

### Docker

```bash
docker compose up --build
```

Поднимаются PostgreSQL и приложение на `http://localhost:8080`. Первый опрос — сразу после старта,
дальше раз в `BINANCE_POLL_INTERVAL`. Настройки задаются переменными окружения или в файле `.env`
(шаблон — `.env.example`), без них берутся значения по умолчанию:

```bash
BINANCE_POLL_INTERVAL=PT10S BINANCE_SYMBOLS=BNBUSDT,ETHUSDT docker compose up --build
```

### Локально

Нужны JDK 21 и Docker для базы:

```bash
docker compose up -d postgres
./mvnw spring-boot:run
```

База из compose опубликована на порту 5433, чтобы не конфликтовать с локально установленным PostgreSQL.
При локальном запуске настройки берутся только из переменных окружения, файл `.env` читает лишь compose.

### Тесты

```bash
./mvnw verify
```

Запускает unit-тесты и интеграционные `*IT`. Для интеграционных нужен Docker: PostgreSQL поднимается
через Testcontainers, Binance подменён WireMock. Только unit-тесты: `./mvnw test`.

## API

Swagger UI: http://localhost:8080/swagger-ui.html, health: http://localhost:8080/actuator/health

У всех эндпоинтов необязательный параметр `symbol`, по умолчанию `BNBUSDT`. Пара не из `BINANCE_SYMBOLS` — 400.

`from` и `to` — instant ISO-8601 в UTC (`2026-09-01T10:00:00Z`) или дата (`2026-09-01`).
Дата в `from` означает начало дня, в `to` — весь день. Обе границы входят в период.

### Последняя цена

```bash
curl "http://localhost:8080/api/v1/prices/latest?symbol=BNBUSDT"
```

```json
{"symbol":"BNBUSDT","price":"731.69700546","fetchedAt":"2026-10-20T12:43:51Z"}
```

`fetchedAt` — время получения ответа от Binance.

### Средняя за период

```bash
curl "http://localhost:8080/api/v1/prices/average?from=2026-09-01&to=2026-09-30"
```

```json
{"averagePrice":731.16666667}
```

### Цены за период

```bash
curl "http://localhost:8080/api/v1/prices?from=2026-09-01&to=2026-09-30&page=0&size=20"
```

```json
{"items":[{"symbol":"BNBUSDT","price":"730.00000000","fetchedAt":"2026-09-01T10:00:00Z"}],"page":0,"size":20,"totalElements":135,"hasNext":true}
```

`size` от 1 до 100, по умолчанию 20. Записи идут по `fetchedAt` по возрастанию.

### Тренд

```bash
curl "http://localhost:8080/api/v1/prices/trend?from=2026-09-01&to=2026-09-30"
```

```json
{"symbol":"BNBUSDT","start_date":"2026-09-01","end_date":"2026-09-30","trend":"UPWARD"}
```

`trend` — `UPWARD`, `DOWNWARD` или `FLAT`. Даты в snake_case, как в примере из задания.

### Ошибки

Ответ в формате RFC 7807 (`application/problem+json`):

```json
{"type":"about:blank","title":"Bad Request","status":400,"detail":"from (2026-09-02T00:00:00Z) is after to (2026-09-01T23:59:59.999999Z)","instance":"/api/v1/prices/average"}
```

| Статус | Когда                                                                                     |
|--------|-------------------------------------------------------------------------------------------|
| 400    | пара не из конфигурации, нет `from`/`to`, неверный формат, `from` позже `to`, `page`/`size` вне диапазона |
| 404    | нет данных: ни одной записи для `latest`, ни одной цены в периоде для `average` и `trend`   |
| 422    | для тренда в периоде меньше двух цен или все получены в одну секунду                      |

## Решения

### Опрос и ошибки Binance

- `@Scheduled` с `fixedDelay`: следующий тик отсчитывается от конца предыдущего, медленный ответ не копит очередь.
- У HTTP-клиента явные таймауты — иначе зависшее соединение навсегда заняло бы поток планировщика.
- Ошибка одной пары не мешает остальным. 5XX, таймаут и некорректное тело — warn, пара пропускается до
  следующего тика, повтора внутри тика нет. Остальные 4XX, например `-1121 Invalid symbol`, — error.
- 429 и 418: опрос всех пар останавливается до момента из `Retry-After`, потому что лимиты Binance считаются
  по IP, а не по паре.

### Rate limits

`avgPrice` весит 2, лимит `REQUEST_WEIGHT` — 6000 в минуту на IP (по `/api/v3/exchangeInfo` на октябрь 2026).
Расход в минуту: `2 × число пар × 60 / интервал в секундах`. По умолчанию (1 пара, 30 с) — 4, то есть 0,07% лимита;
при интервале 30 с лимит выдержит до 1500 пар. Фактический расход по IP Binance возвращает в заголовке
`X-MBX-USED-WEIGHT-1M`, сервис пишет его в DEBUG-лог: IP могут делить и другие процессы.

### Дубли и потеря данных

- Хранится и `fetched_at` (часы сервиса), и `close_time` из ответа Binance (время последней сделки).
  Уникальный ключ `(symbol, close_time)` и `INSERT ... ON CONFLICT DO NOTHING`: повтор тика или отсутствие
  новых сделок не дают дублей, которые исказили бы среднюю.
- Запрос к Binance выполняется вне транзакции, сохранение цены — отдельная транзакция из одного INSERT.
  Частично записанных данных не бывает.
- `avgPrice` — снимок текущего состояния, истории у эндпоинта нет. Тик, пропущенный из-за сбоя,
  восстановить нельзя. Гарантия другая: каждый полученный ответ сохраняется ровно один раз.

### Несколько экземпляров

От дублей защищает уникальный ключ. ShedLock нужен, чтобы N реплик не обращались к Binance N раз за интервал:
вес считается по IP, и лишние запросы приближают 429. `lockAtMostFor` равен интервалу — упавшая реплика
задержит опрос не больше чем на интервал. `lockAtLeastFor` — половина интервала: на все реплики не больше
двух опросов за интервал. Время блокировки берётся из базы, расхождение часов реплик не влияет.

### Деньги и время

- Цена — `BigDecimal` и `NUMERIC(20, 8)`. Строка из ответа Binance сразу разбирается в `BigDecimal`.
  Scale 8 — максимальный `quoteAssetPrecision` на спотовом рынке Binance, 12 знаков целой части покрывают
  самый большой `maxPrice` (~3·10¹⁰ у BTCIDR).
- Средняя считается в базе по `NUMERIC` и округляется до 8 знаков (`HALF_EVEN`).
- Время — `Instant` и `timestamptz` в UTC. `fetched_at` хранится с точностью до секунды, как и отдаётся в API,
  поэтому `to`, равный показанному `fetchedAt`, включает эту запись.

### Тренд

Наклон прямой МНК (цена от времени), переведённый в относительное изменение за период:
`наклон × (t_последняя − t_первая) / средняя цена`. Суммы для МНК считаются в SQL — точки периода
не загружаются в память. При `|изменение| < TREND_FLAT_THRESHOLD` тренд `FLAT`.

Порог по умолчанию 0,2%: комиссия спотовой торговли Binance для обычного пользователя — 0,1% за сделку,
движение меньше двух комиссий (покупка и продажа) не заработать.

### Пагинация

Сортировка по `fetched_at` по возрастанию: новые записи появляются в конце, поэтому прочитанные страницы
не сдвигаются, пока сервис продолжает опрос.

## Ограничения

- Средняя — арифметическое среднее выборок, а не среднее, взвешенное по времени: при пропусках тиков
  оставшиеся точки весят больше.
- Пауза после 429/418 хранится в памяти экземпляра; другие реплики узнают о лимите из собственного 429.
- Пока на рынке нет сделок, `closeTime` не меняется и новые записи не появляются, поэтому в тихие периоды
  точек меньше.
